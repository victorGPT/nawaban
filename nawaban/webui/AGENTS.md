# webui design rules

This project uses shadcn/ui on Base UI (React + Tailwind CSS v4, source-owned components under `src/components/`). These rules always apply when writing UI code.

## Three layers

1. **Headless** — `@base-ui/react`. Only `src/components/ui/` may import it.
2. **Styled kit** — `src/components/ui/`, generated by the shadcn CLI. Tokens live in `src/styles/theme.css`, the shadcn token bridge in `src/styles/shadcn-tokens.css`, typography in `src/styles/typography.css` and `src/styles/nawaban-typography.css`.
3. **App** — `src/App.tsx`, `src/views/`, `src/components/*.tsx`, the feature folders `src/components/<name>/` and the app-specific compositions under `src/components/application/`. These import from `@/components/ui/*`, never from `@base-ui/react`.

Inside the app layer, a screen is split by who talks to the backend:

- `src/views/<name>/index.tsx` fetches (through `@/lib/api`), owns loading, error and stale-response handling, and assembles components. It may import anything in `src/components/` and `src/lib/`. Only `src/App.tsx` imports a view.
- `src/components/<name>/` (for example `task-detail/`, `disclosure/`) is presentational: data and callbacks arrive as props, one section per file, no fetch and no `@/lib/api` calls. It may import other `src/components/` files, `@/components/ui/*` and pure helpers from `src/lib/`, never `src/views/`.
- `src/components/ui/` imports neither of the above.

Task detail is the first screen on this split; the other top-level `src/components/*View.tsx` files still fetch for themselves.

`src/lib/component-origin.test.ts` enforces layers 1 and 3: a `@base-ui/react*` import outside `src/components/ui/` fails, and so does a reappearance of the retired `src/components/base/` or `src/components/foundations/`. It also fails on a native control (`<button>`, `<input>`, `<a>`, …) anywhere under `src/views/` or `src/components/`, at any depth, except the generated `ui/` and the grandfathered `application/`. And it fails when a file in a feature folder `src/components/<name>/` (again excluding `ui/` and `application/`) imports or re-exports `@/lib/api` or anything under `src/views/`, by alias or relative path; top-level `src/components/*.tsx` files are not held to that rule yet.

## Adding a component

- Need a control that is not in `src/components/ui/`? Install it: `npx shadcn@latest add <name>` (answer **no** if it offers to overwrite an existing file). `components.json` pins style `base-nova` with the Base UI registry; do not hand-write files into `ui/`.
- Generated files need two edits every time: repoint `import { cn } from "cn"` to `@/lib/utils`, and delete the `react-day-picker` / duplicate dependencies the CLI may add (this repo uses `@daypicker/react`).
- Import through the `@/` alias, e.g. `import { Button } from "@/components/ui/button"`.
- Delete a `ui/` file once nothing outside tests imports it; one CLI command brings it back.

## Editing generated files

The Figma design needs variants shadcn does not ship. Add them **inside the generated file**, in its `cva` block, the normal shadcn way — never by wrapping the component or overriding it from layer 3. Every such edit carries a comment at the top of the file starting `BoardUI delta to the generated base-nova <component>`, and is listed in [UI.md](UI.md). Regenerating a component means re-applying its listed deltas.

## Color: semantic tokens only

- Never use raw palette classes (`text-gray-500`, `bg-white`) or hex/oklch literals. Every color rides a semantic token, which also makes dark mode automatic.
- Text: `text-text-primary`, `text-text-secondary`, `text-text-tertiary`, `text-text-placeholder`, errors `text-text-error-primary`.
- Surfaces: `bg-background-primary-default`, `bg-background-secondary-default` / `-hover`, `bg-background-tertiary-default`, page ground `bg-background-full`.
- Borders: `border-border-button-default` / `-hover`, hairlines `border-separator-border`, tables `border-border-table`, checkboxes and radios `border-border-checkbox-default`.
- Icons: `text-foreground-icon-primary` through `text-foreground-icon-quaternary`.
- shadcn's own vocabulary (`bg-primary`, `border-input`, `text-muted-foreground`) is aliased onto these in `src/styles/shadcn-tokens.css`. Use it inside `ui/`; prefer the semantic names outside.
- Dark mode flips tokens via the `.dark` class on `<html>`. Do not write `dark:` overrides with raw colors.

## Typography: composite utilities only

- Use the composite type utilities: `text-title-1-medium`, `text-headline-medium`, `text-body-medium`, `text-body-regular`, `text-body-2-*`, `text-caption-1-semibold`, and friends. Each sets size, weight, line-height and letter-spacing together.
- Never rebuild type by stacking `text-sm font-medium leading-5`; if a style seems missing, look in `styles/typography.css` first.
- Merge classes with `cn()` from `@/lib/utils` (or `cx()` from `@/utils/cx` for plain strings). Both know about the composite `text-*` utilities; a plain `tailwind-merge` drops them. No string concatenation, no `clsx`.

## Spacing, shape and mechanics

- Stay on Tailwind's spacing scale; prefer flex/grid `gap` over per-child margins. Arbitrary values only when matching an existing component exactly.
- Cards and panels: `rounded-3xl` with `border-border-button-default`. Inputs and menu rows: `rounded-md` to `rounded-2lg`. Pills: `rounded-full`.
- Legacy rules in `src/index.css` are the reference-kanban skin. Anything there that can override a Tailwind utility on a `ui/` component belongs in `@layer base`, or the utility silently loses.
- Icons come from `@remixicon/react` in layers 2 and 3; `lucide-react` appears only inside generated `ui/` files.
- Use the shared `bui-popup-layer`, `bui-tooltip-layer` and `bui-toast-layer` classes for portals above dialogs; test Escape, outside dismissal and focus restoration when changing overlays.
