# Changelog

## Unreleased

- The merge gate now blocks `gh pr merge` while `main` is red, except for fix PRs. `main` is red when a workflow triggered by `push` on `main` has failed (`failure`, `timed_out` or `startup_failure`) on its latest run that is not `cancelled`, `skipped` or `neutral`, among the last 50 push runs `gh run list --branch main --event push` returns. The push filter runs on GitHub's side: on agent-center only 6 of the last 50 `main` runs were push runs, so filtering after the fact could miss a red one. Runs triggered by `schedule`, `workflow_run`, `workflow_dispatch` and other events do not count, so a failed probe or post-deploy check does not freeze merges. Plugin version is now `0.1.3` in both manifests, so GitHub installs receive this change. A later success of the same workflow, from a re-run or a new commit, lifts the freeze. Workflows are told apart by their ID, so two workflows with the same name cannot hide each other's failure; the claim stop gate groups the same way. While a run is being re-run (not finished, attempt above 1), the merge gate counts that workflow as red and says it is re-running; the claim stop gate still skips unfinished runs. A PR whose title starts with `Revert` or that has the `main-fix` label merges as before, and the gate skips the query for it. The block message lists each red workflow with its run link and how to get through. A failed or malformed run query blocks, as other gate queries do, and so does any run missing `event`, `status`, `url`, `createdAt`, or both `workflowName` and `workflowDatabaseId`; the query shares the gate's 8-second limit. Known limit: a deleted workflow whose last run failed keeps merges frozen until it drops out of the last 50 push runs; use the `main-fix` label meanwhile.
- Plugin version is now `0.1.3` in both manifests, so GitHub installs pick up the second-`handoff` change in the next entry: a second `handoff` on a task this session already handed off now points at `nawaban event <ID> --body "..." --now "..."` for refreshing the task's current state. That change merged without a version bump, and a GitHub install only updates when the version changes.
- A second `handoff` on a task this session already handed off and still holds now says so and names the command that refreshes the board's current state: `nawaban event <ID> --body "..." --now "..."`. That command already worked after a handoff; the old message only said `先 claim/start`, and `start` refuses an `in_progress` task, so a worker who pushed a fix after review had no visible way to update `now`. A task this session never handed off, or one another owner holds, gets the same result and message as before. The task skill's wrap-up reference says the same.
- Plugin version is now `0.1.2` in both manifests. The merge gate no longer blocks every PR whose checks are empty. When checks are empty, it reads `.github/workflows` on the PR's base branch and on the PR head in one GraphQL query, on the PR's own GitHub host. It still blocks when any workflow can run on the PR: `pull_request*`, `merge_group`, a `push` with no branch filter, a `push` whose branches include the PR branch or a glob, and anything the parser cannot read (quoted strings or flow collections that span lines, escaped or quoted-character names, multi-document files). Only a direct `branches:` key of `push` counts as a filter. With no such workflow, the merge passes only when an unfinished task has the PR's full URL as a `pr` ref, its latest review passes on the PR head, and `gh pr merge` carries `--match-head-commit` with that commit; with no such task it is still blocked. Pending or failed checks block as before, and so does a failed workflow query. The whole merge check now has an 8-second limit, shared by every `gh` call and the board read, so it ends with a block before the 10-second hook timeout, which would otherwise let the merge run. CI that is not a GitHub Actions workflow is not detected. On bzkanbanv2 PR #41, which has only a push-to-`main` deploy and a manual deploy, a merge locked to the reviewed head passed the gate in a dry run and an unlocked one was blocked.
- A PR behind `main` can now merge without `gh pr update-branch` and another CI round when `main`'s new commits cannot affect its CI result: either every one of them carries a GitHub Actions skip marker (`[skip ci]`, `[ci skip]`, `[no ci]`, `[skip actions]`, `[actions skip]`), as deploy-pointer commits do, or none of the files they change is a file the PR changes. A renamed file counts under both its old and new name, on either side. The merge still blocks when the two sides share a file, and when both sides add a file under a `migrations/` directory (copying or renaming one in counts), even with different names, because migration numbers or Alembic heads can clash. When a merge passes this way the gate adds a line to the agent's context saying why, and, for the no-shared-file case, that `main` CI is the backstop after the merge. The gate also blocks when it cannot read the full lists: `main` is more than 250 commits ahead, `main`'s side changed 300 files or more, or the PR's file list does not match its changed-file count (one page of 100 files is read). `compare/<head>...main` replaces `compare/main...<head>`, and a PR that is behind costs a third request, `pulls/<n>/files`, which returns the old name of renamed files. That request gets only what is left of the merge check's shared 8-second limit (see the `0.1.2` entry above), so the hook stops before its 10-second timeout lets the merge run unchecked; with too little time left the gate blocks. On agent-center PRs the three requests took 1.1 to 2.2 seconds.
- Plugin version is now `0.1.1` in both the Claude Code and Codex manifests. Claude Code delivers new code to a GitHub install only when this version changes: under an unchanged version, `claude plugin update` reports the plugin as current and keeps the old cached commit. `docs/release.md` records the test and says to raise the version in any PR meant to reach users. It also describes running the hooks from a separate clone that only follows `main`, with one command to publish (`git pull --ff-only`) and one to roll back (`git reset --hard ORIG_HEAD`).
- `review <ID> --commit <SHA> --findings <JSON>` records a review on the task: the reviewed commit and each finding's severity, evidence and whether it was already there. A fixed rule decides pass or fail: a finding at `major` or worse blocks unless it was already there, and a `critical` without evidence counts as `major`. Three failed reviews in a row put one `decide` ask in the inbox, once per failing streak, in the same transaction as the review. When an unfinished task on the board has the PR's full URL as a `pr` ref, the merge gate now requires that task's latest review to pass on the PR head and `gh pr merge` to carry `--match-head-commit` with that commit. Only the host, owner, repository and number in the URL count; done and cancelled tasks are ignored, and PRs no unfinished task refers to keep the CI-only gate. `ref --kind pr` now writes a bare number (`39`, `#39`) as the full URL of the current checkout's GitHub remote, and refuses it when there is no Git checkout, no GitHub remote, or remotes pointing at different repositories. Bare-number `pr` refs already on tasks are not migrated and do not count toward the review gate, so merging those PRs is checked by CI only until a full URL is registered.
- `dispatch` inside Herdr now opens one tab per worker instead of splitting the director's pane: by the fifth split a pane is a few rows high, Herdr cannot read the agent's state, and the brief loses its Enter. The brief is sent once with `agent prompt --wait`; when Herdr does not see the worker start, dispatch presses Enter again up to three times and never retypes the text. Herdr commands no longer inherit the director pane's `HERDR_PANE_ID`, `HERDR_TAB_ID`, `HERDR_WORKSPACE_ID` or `HERDR_SESSION`; the workspace is passed explicitly. Each Herdr worker gets a detached watcher (`python3 -m nawaban.dispatch watch`): when its pane, tab or workspace closes before the card is finished or handed off, the card gets a `pane closed` event and the director is woken with a message, with no listener to start. Only Herdr's `pane_not_found` or `server_not_running`, seen twice 2s apart, counts as closed, so a timeout or a Herdr restart is not reported. A watcher answers only for its own dispatch: once that dispatch is dismissed or replaced by a new one, it writes nothing. Whether a card is finished or handed off, for the watcher and for `dismiss`, now looks at the session of the current dispatch, so an earlier worker's handoff no longer hides a new worker's closed pane or lets `dismiss` stop a new worker. On herdr 0.9.4, 10 parallel calls of the Herdr start path under full CPU load, with a short test prompt and without worktrees, all started their turn, and a closed tab reached the card in 2.1s. The director skill and worker protocol say not to mark a worker blocked with `herdr pane report-agent`, because Herdr then rejects `agent prompt` to that pane.
- The four skills, their references, `BOARD.md` and `TEMPLATE.md` are now in English, using the terms in `GLOSSARY.md`. `TEMPLATE.md` keeps its `## 对齐` and `## 时间线` headings, which `import_md.py` matches verbatim, and the old done-gate value 「纯内部·CI收口」; `tests/test_template_import.py` parses the template with the importer. CLI output, hook messages and code are unchanged. `scripts/skill_shelf.py` reads the task skill's `## External capabilities` heading, and `tests/test_dispatch.py` checks the worker protocol for `named sub-agent`. In `docs/skill-trigger-evaluation.md` should-load cases loaded a skill first in 116/138 runs before and after, and no should-not-load case loaded one.
- `scripts/eval_skill_trigger.py` adds seven wrap-up and handoff cases and records which nawaban skill loaded first. Folding `nawaban-wrapup` into the task skill was measured and not adopted: Sonnet loaded a skill first on 11/21 wrap-up runs, down from 19/21 (`docs/skill-trigger-evaluation.md`).
- The director skill now replies to a dispatched worker with `notify --kind reply`, matching the worker protocol; stopping and resuming the session is kept only for a director window that did not dispatch the worker. It also re-runs `dispatch --parent` after each child card passes, describes an optional integration branch for cards that ship together, and reviews the combined diff before closing a batch. The director now merges a card's PR itself once the card passes acceptance, a review finds no blocking issue and checks are green; a merge that deploys to production still goes to the user. The worker brief now says not to merge PRs and to bring the target branch in before opening one.
- The bilingual glossary is now `GLOSSARY.md` instead of `CONTEXT.md`, the name the upstream domain skills read since their v1.3.0. Its format is unchanged; README, the web UI notes and `tests/test_glossary.py` point at the new name.
- The task skill's gate table and PR notes now document the merge gate: run `gh pr merge` as a single command on a branch that contains the latest main with all checks green. No gate decision changed.
- The `nawaban` skill description now says to use it before changing files, committing or branching in a repository with a board, and the skill tells sessions to give shell writes an absolute path inside the worktree, because the write gate does not follow `cd`. In `docs/skill-trigger-evaluation.md` sessions loaded the skill before acting in 34/42 held-out runs, up from 27/42, and gate rejections fell from 27 to 5.
- `scripts/eval_gates.py` reports each pass rate with a 95% interval, counts unfinished runs and skill loads, and says when a score has no headroom or two variants differ by less than the noise. New `scripts/eval_skill_trigger.py` measures whether a session loads the task skill before acting and stays away from it otherwise, with a held-out split and `--regrade` for saved transcripts.
- `create` without `--epic` now fills the module when the TypeSafe answer reaches 0.9, with the score recorded in a note, instead of only printing a suggestion. Cards created while the suggestion was print-only stayed ungrouped.
- Mark a Done task as regressed when a later change breaks it: `nawaban link <fix> <done task> --kind regresses --note "<which merge>"`. The task stays Done; the board and module view show a red Regressed mark until the fix task is done, and the graph API reports it as a flag. `nawaban blame <files>` lists the tasks whose merges changed those files. When a project's main CI is red and no unfinished fix task was linked since the red streak began (any unfinished fix counts when the start is older than the 30 listed runs), `claim` refuses; `--override "reason"` passes and is recorded. A red result older than 5 minutes is re-checked before refusing. The session banner shows red or unreadable CI status, refreshed in the background at most every 10 minutes. The first CLI command after upgrading rebuilds `task_edges` once to accept the new kind.
- Remove the compatibility names that need no data migration: the hidden verbs `kin`, `advance`, `letter`, `letters` and `letter-read`; the `--origin` and `--origin-file` flags; the `FOREMAN_OWNER` and `FOREMAN_ALLOW_BRANCH_SWITCH=1` inputs; all `WORKOS_*` environment variables; and the root `foreman_card.py` / `foreman_liveness.py` import shims. Old verbs and flags fail as unknown input; old environment variables are ignored, so rename them where you set them (for example `WORKOS_CONTEXT_BANNER` in Claude settings and `WORKOS_DB` in a launchd backup job). `tests/test_glossary.py` fails if an alias registration, a retired environment name, a root shim, or a hint to a retired verb returns.
- Prefer `NAWABAN_OWNER` for the session identity and `NAWABAN_ALLOW_BRANCH_SWITCH=1` for the branch gate escape prefix. The board's inbox and capture writes now set `NAWABAN_OWNER`, so an exported owner cannot replace their fixed identities.
- Rename the project setup skill from `foreman-pattern` to `nawaban-setup`. Reinstall or relink the skill if you linked it by its old directory name.

- Add English and Chinese board languages, selected from the browser language and switchable in the sidebar with a saved preference. Preserve existing Chinese wording and stored API values. Show Assigned separately from In progress, and enforce English message registration in CONTEXT.md.

- Session state uses `NAWABAN_STATE_DIR`, then `~/.local/state/nawaban`. If the new session registry is absent, reads fall back to `~/.claude/foreman/session-registry.json`; the next registration preserves those entries in the new file and leaves the old file untouched. An existing new registry takes precedence.
- Stale reports and daily markers independently fall back to `~/.claude/state` when their new files are absent. A legacy marker for today prevents duplicate background checks; subsequent checks write only to the current state directory and leave legacy files untouched.
- `init` reuses an existing `.foreman/workos.db` when `.nawaban/nawaban.db` is absent, preventing a second board from splitting task history. Explicit database selections still take precedence.
- Board writes require JSON and validate Host and Origin against the local listener before invoking the task CLI.
- Prefer `deps`, `transition`, `notify`, `notifications`, and `notify-read`. `fanout` and `wrapup` are unchanged.
- Rename `tasks.origin` to `context` with an idempotent `ALTER TABLE ... RENAME COLUMN` migration. New boards use `context`. Board APIs, web UI, context loading, and imports consume `context`; detail headings are unchanged. Existing boards migrate on their next CLI command, so upgrade all readers and writers together; do not point this version at a board still served by the legacy runtime.

- Rename the runtime directory, imports, CLI display name, board branding, and source references from `workos` to `nawaban`. CLI subcommands, enum values, and database schemas are unchanged.
- Prefer `NAWABAN_DB`, `NAWABAN_BOARD_PORT`, and `NAWABAN_BOARD_HOST`. The same applies to the home, context-banner, and decision-channel settings.
- Use `.nawaban/nawaban.db` for new boards in the shared Git checkout or nearest board directory. Reads and `init` reuse `.foreman/workos.db` when the new database is absent. An explicit `--db` or database environment override still takes priority. Database files are not moved by this path selection.
- Derive board startup and reconciliation paths from the checkout, current directory, and explicit configuration instead of personal directories. Keep rotation of legacy `workos-*.db` backups and explicitly selected legacy board executables compatible.
