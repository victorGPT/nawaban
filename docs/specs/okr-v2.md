# OKR 系统 v2：读数能当编排者自治闭环的传感器

> 起草：2026-11-25，NAWABAN-OKR-V2。这是一份只改设计的规格，没写代码。
> 依据：NAWABAN-REVIEW-OKR 评审报告 `~/.nawaban/reviews/okr.md`（下称「报告」）。决策者 11-25 定「按报告作者的想法改」，报告 C 节改进 1–5 和 A 节「没提但该关心的」都采纳为方向，只有职责分离 review 不做。本仓库 `board/src/okr.ts`、`GLOSSARY.md`；roubao `docs/agents/okr.toml`（11-25 读）。
> 前置票：NAWABAN-OKR-SENSOR，做去重键、量法哈希、新序列和「量不了」。本文只引用它的结论，不重复它的内容。

## Problem

编排者用 `nawaban okr` 的读数来决定「全 ✓ 收工」，还是「两轮不动就停」。报告实测发现这些读数不可信，坏在四处：

1. 面板会停在旧值上（C1，由 SENSOR 修）。
2. 改量法会被记成进展（C2）。
3. ↓ 声明从来不判（C3）。
4. 判定没有误差区间，而且护栏说的「轮」和代码里的「轮」不是一回事（C4）。

另外，影响声明都是关票时才写（C5），这时已经看过数了。产出型 KR（数子票完成了几张）很容易变绿，会让「全 ✓」失真。

- **v2 只做在板 CLI 上**（`board/src/`），不改 `nawaban/cli.py`。理由：旧 CLI 在 MIGRATE-10 之后只剩读历史，在它上面再做一遍是白做。这是本票 worker 的建议，**待决策者确认**（needs-info 第 2 问）。
  - 代价：唯一有 okr.toml 的 roubao，要等 NAWABAN-MIGRATE-10-05 把 OKR 三张表导入本地板才用得上 v2。认领时预注册还要等 MIGRATE-10-03 把写路径切过来。这两条依赖写成 V2-06 的前置。
  - 在那之前，v2 的验证都用 fixture 或账本副本回放。
  - 另一个选法：v2 两边都做，也就是 `cli.py` 也改。roubao 能马上用上，代价是同一套判定写两遍、测两遍，MIGRATE-10-05 之后还要删一遍。
- **第二本账**（报告 C1）：在旧 CLI 记账的仓库里（`hooks/route.mjs` 打印 `old`），跑板 CLI 的 `okr` 现在会另写一个 `okr/<project>` 频道，面板不读这个频道。v2 还会往里面记轮次和硬停，所以从 V2-04 起，这种仓库里的板 CLI `okr` 直接拒绝，并提示改用旧 CLI。MIGRATE-10-05 删掉分流时，这条拒绝一起删。

- 不做职责分离 review（决策者否了）。

## 0. 前置：NAWABAN-OKR-SENSOR（已在做）

- 读数去重键带上 `def_hash` 和数值。`def_hash` 是三样东西的内容哈希：okr.toml 里该条 KR、它调用的 `scripts/kr` 脚本、评测集和金标文件。
- `def_hash` 一变就开新**序列**，面板标「口径 vN 起」。趋势、预期不符、停滞都在当前序列里从零算。
- 测量失败显示「量不了」，不沿用旧读数亮绿。

下文说「序列」都指 SENSOR 定义的同一 `def_hash` 下的读数。

## 1. 数据形状

### 1.1 读数带样本量

measure 最后一行现在打印的是 `<数值> <截至> <来源>`。v2 允许在来源里带 `n=<题数>`，例如 `92.5 2026-11-20 n=40 cases/intent`。

- 单位是 `%` 且带 `n` 的读数算**比例读数**，可以算区间。
- 不带 `n`、或单位是「次」「张」「个百分点」的，算**点读数**。点读数没有区间，噪声门对它不生效，退回现在的精确比较。
- 读数 block 加一个字段 `n?: number`。旧读数没有这个字段，按点读数处理。

### 1.2 KR 带类型

okr.toml 的每条 KR 加 `kind`，取值只有两种：

| kind | 含义 | 怎么判 |
| --- | --- | --- |
| `committed`（承诺型） | 硬拦、合规、冒充这类「必须成立」的线，当 SLO 闸 | 按点值精确判，一次不过就算破线。破线时在「要你盯」出一条 `breach`，该 O 的收工条件不成立 |
| `aspirational`（进取型） | 要往上推的目标 | 打 0–1 分（见 §4），绿灯取区间界（见 §2） |

- 没写 `kind` 的 KR 按 `aspirational` 读。这样 v2 上线时不用先改 okr.toml。
- 不设「产出型」这一类。子票完成数这种 KR 由决策者决定移出 OKR，或改写成结果型（见草案）。v2 不在代码里认它。

### 1.3 影响声明预注册

声明从「关票时写」改成「认领时登记，关票时补结果」：

| 时刻 | 写什么 | block |
| --- | --- | --- |
| 认领（`claim` 带 `--o --kr`，或认领后、第一条 PR link 之前的 `event --kind impact`） | O；每条 KR 的方向（`toward` 向目标、`away` 背离目标、`hold` 不变）、登记时的读数（取当前序列最新值，CLI 自动填）、量法版本（当前 `def_hash` 的序列号，CLI 自动填）、改动类别 `change` | `nawaban-impact@2` |
| 关票（`close --done`） | 只补结果：每条 KR 的 after 值和依据（实测或预计）。方向、读数、量法版本不能再改 | 同一条声明的 reply `nawaban-impact-result@1` |

- **改动类别** `change` 取 `product`（改产品）、`measure`（改量法）或 `gold`（改金标或数据集），默认 `product`。只有 `product` 算进展。`measure` 和 `gold` 的声明不判对错，也不计进 O 的 toward/away/hold 条数，面板单列成「改尺子 N 张」。
- **事后声明**：第一条 PR link 之后才登记的声明，标「事后」。照样满足关票锁，但不判对错、不计数。这样关票锁不会因为 v2 上线一下子拦住所有在做的票。
- 关票锁不变：仓库有 okr.toml 时，没有声明的票 `close --done` 被拒。v2 额外要求，`impact@2` 声明了 KR 的，关票时要补结果，否则拒。
- O 为「无」的声明照旧，一行就够。
- **旧声明**（`nawaban-impact@1` 的 ↑↓=）在读取时换算，不改数据。有前后值的，按前后值相对目标的远近定 toward 或 away。没有前后值的，↑ 对 `>=` 型 KR 读作 toward，对 `<=` 型读作 away，↓ 反过来，= 读作 hold。换算出来的一律标「事后」，因为它们都是关票时写的。

### 1.4 轮与停

- **一轮 = 编排者的一次自查 = 一次 `nawaban okr`**（会跑 measure 的那个动词；`json okr`、面板、网页只读，不算轮）。CLI 在 `okr/<project>` 记一条 `nawaban-okr-round@1 { n, at, kept, moved }`。
- 本轮没有新记任何读数的，记作**空转**（`kept = 0`）。
- 每个 O 有一个**冲刺**：从它最近一次被 accept、或最近一次 `okr --resume <O>`（没有的话从 v2 上线）起算，往后数轮数。
- **硬停**，满足任一就停：
  - 连续两轮，该 O 没有任何进取型 KR 在当前序列里往目标「动了」（按 §2 判，「未定」不算动），包括空转的轮；
  - 冲刺内满 5 轮，O 还没收工。
- 硬停时：
  - `okr` 退出码非 0，打印「硬停：<O>」；
  - 把一份待决策项草稿写到 `~/.nawaban/board/okr-stop/<project>-<O>.md`，内容按 GLOSSARY 的「待决策项」格式：
    - 决策事项：<O> 下一步怎么走；
    - 关联 KR：没动的 KR；
    - 背景：这个冲刺试过什么，也就是冲刺内声明过的票、各自的方向和判定，以及每轮各 KR 的读数；
    - 备选方案至少三条：换打法继续、降目标、改量法或数据集，后两条标「只有你能定」；
    - 建议：留给编排者填。
  - 草稿不自动发出去。编排者补上「建议」后用 `event --kind ask` 发。这样待决策项照旧过就绪标准。
- 硬停之后，同一个 O 再跑 `okr` 还是非 0，直到决策者对那条待决策项 resolve，编排者再跑 `okr --resume <O>`。没有一张 resolve 过的、挂在该 O 上的待决，`--resume` 会拒绝。
- AGENTS.md 里的「连续两轮读数不动或跑满 5 轮，停下给我决策卡」（原文）改由这条机制执行。文字留着，作为对人的解释。

## 2. 方向与噪声门

### 2.1 区间

**现有题数下，有些目标永远过不了区间这一关**（下表数字是本票用 Wilson 公式实算的）：

| 目标 | 全对或 0 错时区间界 | 要过线最少要几题 |
| --- | --- | --- |
| >= 95 | n=40 下界 91.2 | 73 |
| >= 97 | n=40 下界 91.2 | 123 |
| >= 80 | n=6 下界 61.0 | 16 |
| >= 90 | — | 35 |
| <= 5 | — | 73 |
| <= 3 | — | 123 |
| <= 20 | — | 16 |

意图（40 题，≥95）、工具调用（40 题，≥97）、E5（6 题，≥80），按「绿灯取区间界」就算全对也亮不了绿。扩题还是降目标，**只有决策者能定**（needs-info 第 1 问）。V2-01 的回放要给每条 KR 出一行：现在的 n、能不能过线、最少要几题。

比例读数用 Wilson 95% 区间：`p = 值/100`，题数取 `n`。

- **进取型绿灯**：`>=` 型取区间下界过线，`<=` 型取区间上界过线，`==` 型要区间同时包含目标且点值等于目标。点值过线但区间没过的，显示「未定（区间 [a, b]）」，不算达标。
- **承诺型**不用区间，按点值精确判（§1.2）。

### 2.2 最小可检测效应（MDE）

同一序列里相邻两轮 `(p1, n1)`、`(p2, n2)` 的变化 `Δ = p2 − p1`，噪声门是：

```
MDE = z · sqrt(p̄(1−p̄)(1/n1 + 1/n2))，p̄ 为两轮合并比例
```

`z` 由回放定（§2.4）。点读数的 MDE 是 0，也就是退回精确比较。如果某条 KR 有 A/A 测出的同 commit 波动 `σ_AA`，就取 `max(上式, 2·σ_AA)`。A/A 怎么跑、存在哪里，不在本文范围，等回放票的结论再说要不要做。

### 2.3 判定

声明之后的第一轮对比声明登记时的读数，判出下面三种之一：

| 声明 | 往目标走了 ≥ MDE | 变化小于 MDE | 离目标远了 ≥ MDE |
| --- | --- | --- | --- |
| toward | 符合 | 未定 | 不符 |
| hold | 符合 | 符合 | 不符 |
| away | 不符 | 未定 | 符合 |

- 「往目标走」按 KR 的 target 判：`>=` 型数值变大算往目标走，`<=` 型数值变小算往目标走，`==` 型离目标的距离变小算往目标走。不再按数值大小判（这是对 C3 的修正）。
- 有下面三种情况的不判：声明之后量法版本变了（新序列）；声明的 `change` 不是 `product`；声明是事后的。
- `json okr` 里 `mismatch` 改成 `verdicts: [{ticket, declared, verdict}]`。旧字段保留一个版本，只放「不符」，给面板过渡。

### 2.4 阈值先回放再定

z 取 1.0、1.64、1.96 三个候选，在 SENSOR 修好的账本副本上回放，比较三件事：

1. 报告 C2 列的 E3 七张声明，以及「长对话接着轮」因换集判出的三张不符，各判成什么。
2. 每条 KR 的「两轮没动」在什么时候触发。
3. 绿灯数和现在差多少。

回放用的数据：

- 值：旧账本 `~/.nawaban/nawaban.db` 副本里的 `kr_readings`。E3 那些中间值当年被 `INSERT OR IGNORE` 吃掉了，账本里没有，只能从 `kr_impacts` 的前后值里拿。
- n：账本里没有题数。回放票照 okr.toml 的 KR 名和代理目录的出分文件手填一张「KR → n」表（例如意图 40、E5 6），表贴在票上。

回放的输出是一张对照表，加一个推荐的 z，贴到回放票上，由编排者按表代定，代定要挂到 KR 上记账。如果回放结论是 z 怎么取都不对（例如题数太小，区间宽到什么都判不出），就停下给决策者出待决策项，不硬选。

## 3. GLOSSARY 统一

`GLOSSARY.md`「Impact mismatch」的英文段原来写的是「↓ and = are off their word when it moved away」，代码和中文段是「↓ 不判」，两段对不上。本 PR 先把英文改成和代码一致（↓ 不判），这样词表如实描述现在的行为。v2 的判定落地时（方向与噪声门那张票），中英两段一起改成 §2.3 的三态判定，再新增四个词：「序列」由 SENSOR 加，「轮」「冲刺」「硬停」由本规格加。

## 4. 进取型打分与收工条件

- **分数** `score = clamp((d0 − d) / d0, 0, 1)`。
  - `d` 是当前读数到目标的距离（`okr.ts` 现有的 `distanceToTarget`）；
  - `d0` 是当前序列第一条读数到目标的距离；
  - 已达标记 1；
  - `d0 = 0` 时，未达标记 0，达标记 1。
- 「已达标」按 §2.1 的区间判。
- d0 取序列首值，所以**每次换量法，分数都从 0 重新算**。如果决策者想跨序列比较，可以在 KR 上写 `baseline = "<数值>"` 当 d0。这个字段可选，写了就优先用它。
- **未测、量不了、过期的 KR**：进取型按 0 分计入均分；承诺型算不过线。所以只要有一条量不出来，O 就收不了工。这样可以防止「只有一条量得出、拿了 1.0 分就收工」。O 下面还没接 measure 的 KR（例如 roubao O3–O5 那几条），如果决策者不想让它们挡收工，要在草案里把它们移出，或者写 `wait`。写了 `wait` 的 KR 不计入均分，但在面板上照样显示。
- **O 收工**（取代「全 ✓」）同时满足两条：
  - 承诺型 KR 全部过线；
  - 进取型 KR 的平均分 ≥ `ASPIRATIONAL_DONE_SCORE`。草案值是 0.7，取 Google re:Work 的「0.6–0.7 正常」上沿。这个数属于「KR 怎么量」，**由决策者定**。
- 收工后还是走 `okr --accept` 验收。`attention.accept` 的文案改成「承诺型全过、进取型均分 x.xx，待你验收」。
- 面板和网页上，每条 KR 显示类型标记（承诺 / 进取）、分数、区间。O 行显示「承诺 a/b · 进取均分 x.xx」。

## 5. 不在本规格

- 职责分离 review（决策者否了）。
- Brier 打分、按 worker 统计声明命中率（报告 A.12）。v2 的 verdicts 记好之后就能算，等决策者要了再开票。
- 护栏 KR 的非劣效界：只在 KR 草案里建议给 O4 的两条护栏写允许掉多少，代码上 `>= -X` 现在就能表达，不需要新机制。
- 承诺型 KR 接进 roubao 的 CI 或发版闸，那是 roubao 仓库的事，草案点头后在 roubao 开 issue。

## 风险

- **题数太小**：E5 只有 n=6，留存的分母不到 10。噪声门会让这些 KR 长期「未定」，硬停的「没动」也会更容易触发。这是如实反映，不是 bug，但决策者会看到更多黄灯和待决策项。回放票要把这件事量出来。
- **推送格式**：MIGRATE-10-03 的发件箱会把 `影响：` 推到 GitHub。`impact@2` 的推送文案要跟 V2-03 对齐，不然岳不同看到的格式会变两次。
- **轮被灌水**：`okr` 被 worker 或误操作多跑一次，就多一轮空转，可能提前触发硬停。代价是多一条待决策项，方向是保守的，可以接受。
