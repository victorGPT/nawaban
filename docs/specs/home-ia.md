# 首页信息设计（NAWABAN-HOME-IA）

状态：提案，等决策者选方向。本文不改产品代码。原型和截图在本机 `~/nawaban-home-ia/`（一次性的，含另一个项目的真数据，不进仓库）。

## 判据

决策者 11-25：「这个面板是为了降低决策负担、降低认知负担，不要花里胡哨、根本用不到的东西。」

每个元素过一道检验：拿掉它，决策者有没有哪个决定会更慢或更差？没有就拿掉。

## 首页回答的问题

决策者一个人，管 O、拍板，要少打扰。打开首页只问三件事：

1. 有没有要我定的？
2. 这一件，按建议定行不行？
3. 没有的话，我可以走了吗？

## 候选信息的去留

| 候选 | 去留 | 理由 |
| --- | --- | --- |
| 待决策项（有选项和建议） | 留，首页主体 | 首页就是为它存在的。 |
| 等你（只有一句问题） | 留，降级成「问题 + 回一句」 | 拿掉它，这件事没人答，被它挡住的票一直停着。 |
| O 里等决策者动手才能量的 KR（`attention` 的 `wait`） | 方向 A 进单子；方向 B 进那一行 O | 只有决策者能做，不做 KR 一直没读数。 |
| O 的硬停、连续没过、待验收（`stuck`、`five`、`accept`） | 出现时进单子 | 这时它要的就是一个决定。 |
| 各 O 进度 | 去，放 OKR 页 | 没掉红时不改变任何决定。方向 B 留一行，见下。 |
| 今天的结果 | 去，任务页「已完成」列 | 看了不用定什么。 |
| 在推的事 | 去，任务页「进行中」列 | 同上。 |
| 停滞 | 去，任务页「停滞」列 | 停滞归编排者管。要决策者出手时，编排者该把它上升成待决。 |
| agent 和模型 | 留一处小字 | 只写在建议后面（「opus 的建议」），帮决策者判断信不信这条建议。别处不出现。 |
| 刚刚发生 | 去，任务详情的时间线 | 看了不用定什么。 |
| 48 小时内的决策记录 | 去，任务详情 | 答过的卡在原地变成「已交编排者」，够了。 |
| 随手记（现在的「收件箱」页） | 去，自己一页 | 那是决策者写给编排者的，等的是编排者。 |
| 别的项目各有几件等你 | 去 | 首页默认看全部项目，不需要这个数。 |

## 首页结构

一张单子，一列，最宽 680 px：

- 标题一句：「N 件等你定」。没有时整页只有一句「没有要你定的」和看板的时间。
- 最多先露 3 件，第一件展开。其余收在「还有 N 件，没挡着别的」里。
- 每条开头一个小圆点灯。等你定是强调色，答过之后变绿并写「已交编排者」。不用彩色顶条。

一条有两种形态：

- **决策卡**（有选项和建议）：问题一句；选项各一行，带代价；建议的那项已选中并标「建议」；一句理由，后面小字写是哪个模型的建议；主按钮「就这么定：A」；次要按钮「背景不够，退回」；背景折叠。
- **回一句**（只有一句问题）：问题；一个输入框加「发给编排者」；另有「让编排者补成选项和建议」。

答复沿用现有的网页答复（`nawaban-web-answer@1`）：不解除挂起，编排者核实后记已决。

### 单子的规则

1. **一件事只出现一次。** 等你的票，上级也在等你时，并进上级那一条。O 里几条 KR 等的是同一件事时并成一条，写「3 条 KR 因此量不了」。
2. **答过的不再出现。** 挂起之后已有决策者的决策记录，就不再显示。这种票是编排者忘了记 `triage: ready-for-agent`。
3. **按拖延代价排。** 板上没有「拖延代价」这个字段，用现有数据代替：先比挡着几张票（下游加子票），再让有卡的在前（一下就能答完），再比等了多久。这是代替的算法，不是新字段。
4. **单向门不给一键。** 建议的那项是单向门时不预选，要决策者自己点。

## 导航

待决 / 任务 / OKR / 随手记，打开先到待决。

- 首页就是待决页，不另加一页。改动是把 `OPENING_TAB`（`web/src/logic.ts:20`）从任务改成待决，待决页按本文重做。
- 现在的「收件箱」页改叫「随手记」。决策者说的「收件箱」指待决，而 GLOSSARY 里「收件箱」是随手记的想法（Capture Inbox），两个撞名。
- 任务页保持看板。
- 默认看全部项目，每条用小字标项目名。决策者问的是「有没有要我定的」，不分项目。

## 真数据露出来的问题

11-25 凌晨的看板，nawaban 挂着 7 件等你，另一个 GitHub 记账的项目 0 件待决。

1. **7 件里只有 1 件有选项和建议。** 其余 6 件是 `triage: needs-info` 的一句话。现在的待决页只收有卡的（`web/src/decide-logic.ts:37`），今天只显示 7 件里的 1 件。原型照实画成「回一句」，没有替 agent 编选项。根上的办法是要求等你也写成待决策项，这是另一张票的事。
2. **7 件去重后是 4 件。** 2 件是「先看上级票」，1 件决策者已答、挂起没解除。
3. **「一键按建议」缺一个字段。** 建议是一句自由文本（「选 A。……」），原型靠认字母对到选项。要做稳，卡上得记「建议的是第几项」。
4. **没卡的等你没有挂起时间。** `json board` 只给有卡的 `pending.at`。原型从任务事件里取最近一条 needs-info 的时间。
5. **另一个项目板上 0 件待决，但 O 里有 4 条 `wait`**（同因并成 2 件），写明要决策者批。只看板的话首页会说「没有要你定的」，这句话不真。两个方向的差别就在这里。

## 两个方向

| | A 只有决策卡 | B 决策卡 + 一行 O |
| --- | --- | --- |
| O 里等决策者动手的事 | 进单子 | 留在顶上一行里 |
| 省掉哪一步 | 不用去 OKR 页找有没有等我的。只看一处，空了就是真空了。 | 不用点进 OKR 页就知道几条达标、几条没过。 |
| 代价 | 看大局要点一次 OKR。 | 会同时写着「没有要你定的」和「2 件等你动手」，要看两处。那一行天天在，却不要决策者定什么。 |

推荐 A。B 那一行过不了判据：拿掉它，没有哪个决定变慢或变差；真要决策者动的那 2 件，A 已经放进单子了。

## ReUI 能不能直接用

不能直接用。建议不买，只学版式。

- **许可。** 免费的组件是 MIT（[LICENSE.md](https://github.com/keenthemes/reui/blob/main/LICENSE.md)）。票上点名的 4 个 block 页面上都标 PRO。PRO 一次性 249 美元，许可写明不许「Publish the Licensed Materials in a public or open-source repository」（[reui.io/legal/license](https://reui.io/legal/license)）。本仓库是公开的，PRO 的代码进不来。
- **框架。** ReUI 是 React 组件，底下是 Radix 或 Base UI。网页是 Solid 2 加 `@ui-sdk/solid`（ADR 0003，决策者定的）。搬过来等于照着重写。
- **令牌。** ReUI 读 shadcn 的主题变量（`--background`、`--foreground`、`--primary`、`--radius`）。`web/src/ds/tokens.css` 用的是同一套变量名，颜色和圆角已经对得上。缺的是版式，不是组件。
