# 总监派单与 Worker 协议

仅在总监派单或项目明确采用本协议时加载；普通用户任务按 [主流程](../SKILL.md) 执行。

## 项目契约

先读卡；`constraints` 中的 `skills:` 是本卡已选定能力，按当前启用名称解析。方法取决于本次目标：Skill 文案用 writing-for-agents，领域/ADR、原型、TDD 或部署说明仅在对应工作确实需要时加载。

派评审前，核对目标项目共享主树的 `.foreman/director/CONTRACT.md`（若项目声明该契约）。按它确定实际写码 harness、评审执行器、版本与验收责任。必需契约缺失则记录阻塞；普通任务不因不存在总监配置被阻塞。

## 派出与收工

派 worker 用派发命令 `nawaban dispatch`，收工用 `nawaban dismiss`，一张卡一个独立会话：

- 单张：`nawaban --db <目标库> dispatch <ID>`。在目标仓库里执行；它起一个以卡号命名的会话，把任务说明作为第一条消息交给它，并把会话编号写进卡的 now。认领由 worker 进场后自己做。
- 批量：`nawaban --db <目标库> dispatch --parent <父卡>` 只派出从父卡拆出、待办且前置卡都已完成的子卡，其余逐张列出没派的原因；加 `--dry-run` 只看不派，用来对账。
- 收工：卡完成或交接后跑 `nawaban --db <目标库> dismiss <ID>`，停掉会话、关掉窗格、清理工位；工位里还有没提交或没推送的改动时不清理，并说明原因。

不用 Agent 工具起具名子 agent 当 worker：它没有自己的会话编号，看板记不到，消息还会回流到主控窗口。子 agent 只在 worker 内部用于查代码和评审。

判断 worker 是否做完，看卡的状态和来信，不看会话是否显示空闲。

## 汇报

使用同一目标数据库和真实会话身份：

- 阶段进展：`nawaban --db <目标库> notify <ID> --kind stage --msg "<结果、证据与下一步>"`。
- 具体阻塞：写 blocked 信，说明事实和需要的动作；有可独立推进的工作继续处理。
- 验收责任：按项目契约执行，登记实际 acceptance_run 和被审版本；未满足时不报 done。
- 需要用户动作：经 ask 提交材料；notify 汇报状态，两者不互相替代。
- 扩界：按总监契约提交所需路径与理由；得到覆盖该动作的授权并确认 scope 已落板后再编辑。沿用已有授权，避免重复申请。

本地 nawaban notify 是板内记录；外部消息或通知仍需对应授权。结束或交接前记录真实结果与剩余阻塞，不能用 idle 代替交接。
