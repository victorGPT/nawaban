# 协作流程

同事问怎么协作、新人入职时用。状态只存 tracker。仓库的 `AGENTS.md`、`docs/agents/` 和本文冲突时，以仓库为准。

## 谁管什么

- **决策者**：定 O，点头 KR，只答产品怎么表现、对外说什么、上不上生产，随时可推翻任何决定。
- **编排者**：决策者敲 `/nawaban:orchestrator` 声明。拆票、派活、核验收、合并、汇报；KR 以下的事自己定，记成决策。
- **worker**：一票一 PR，由 `nawaban dispatch` 在独立 worktree 里起。
- **评审**：换一个模型审，只报挡合并的问题，附 `文件:行号`。
- **同事**：可在自己机器上另声明编排者管自己那条线。两个编排者互不派活，不替对方合并或拍板；改共享契约或发版，在 PR 里写明并知会对方。

## 一个需求怎么走

1. 记进收件箱，或开 Issue。
2. 编排者用 `grilling` 问到决策者能定的都有答复，`to-spec` 发 spec 票，`to-tickets` 拆票，拆法给决策者看过再派。
3. worker 认领、测试先行、实现。只有决策者能定的记成待决，然后停手。
4. 验收输出贴进 PR。只做了一部分的 PR 写 `Refs #N`，做完才写 `Closes #N`。评审无挡、CI 绿后按仓库的方式合并。
5. 编排者照成功判据核目标，流程走齐不算数；再跑 `nawaban okr`，有红就再派。

## 谁能拍板

做错了能靠 revert 收回的，自己定并记决策。可丢弃的建造（分支、draft PR、dry-run）先做，停在合并和部署之前。收不回的，或涉及权限与密钥、别人的数据、合规、对外表态、产品行为、指标口径、超出授权的花费，只有决策者能定，走 [ask](../ask/SKILL.md)。

## 同事怎么加入

只在 Issue 上协作：评论用 `进展：` `决定：` `PR：` 开头。要让自己的 agent 守同一套规矩：装 nawaban 插件，再读仓库的 `AGENTS.md` 和 `docs/agents/`。

检验：一个新窗口只读 tracker，就能接上任何一张票。
